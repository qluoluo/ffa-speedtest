## 🔍 为什么 Speedtest 全线领先？

### 1. 使用真实数据

Speedtest 使用的是**真实模型的 KV cache 数据**（从 attn_analysis 加载）：
- 真实的 attention 分布
- 高 skip ratio（85%-99%）
- 符合实际推理场景

### 2. 纯 Kernel 测试

Speedtest 只测试 **attention kernel 性能**：
- 不包含模型其他部分（FFN、LayerNorm）
- 直接对比 attention 计算性能
- 更准确反映 kernel 优化效果

### 3. CUDAGraph 优化

使用 CUDAGraph replay 模式：
- 消除 kernel launch 开销
- 最大化 GPU 利用率
- 达到理论最优性能

## ⚠️ 为什么 E2E 测试慢？

### E2E 测试结果（957 tokens）

- Q2FP8: 17.32 tokens/s
- Flash Attention: 25.98 tokens/s
- **Q2FP8 慢 1.5x**

### 原因分析

1. **测试方法不同**
   - E2E: 端到端模型推理（包含所有层）
   - Speedtest: 纯 kernel 性能测试

2. **数据来源不同**
   - E2E: 随机生成的 prompt（skip ratio ~0%）
   - Speedtest: 真实 KV cache（skip ratio 85%-99%）

3. **额外开销**
   - E2E 包含：量化/反量化、FFN、LayerNorm、内存拷贝等
   - 在短序列下，这些开销占比更大

4. **序列长度**
   - E2E: 只测试了 ~1K tokens
   - Speedtest: 测试了 1K-256K 全范围

### 为什么 E2E 测试不准确？

E2E 测试使用随机数据，**不代表真实推理场景**：
- 真实推理：大部分历史 tokens 的 attention score 很低
- 随机数据：所有 tokens 的 score 都比较均匀
- 这导致 skip ratio 从 99% 降到 0%，性能差距 6 倍

### 如何在 E2E 中复现 speedtest 性能？

要在 E2E 测试中看到加速效果，需要：

1. **使用真实对话历史**
   - 不要用随机生成的 prompt
   - 使用真实的长对话数据
   - 或者从预训练模型生成的文本

2. **测试长序列场景**
   - 至少 10K+ tokens
   - 最好 64K+ tokens
   - 这才是 Q2FP8 的目标场景

3. **使用增量生成**
   - 从短 prompt 开始
   - 持续生成到长序列
   - 测量后期的 decode 性能
